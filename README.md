# TEAR — Tamper-Evident Action Recorder

TEAR is a small recorder that sits between an AI agent and its tools. Every tool call, epistemic pause and final
answer is written to a SHA-256 hash chain over RFC 8785 canonical JSON before it takes effect, and the chain is
anchored with RFC 3161 time stamps. In the words of its design: "It makes later tampering with the record
evident. It does not make tampering impossible."

**Origin.** The AI x Epistemics Research Sprint (Apart Research, 13–15 November 2026, Track 2: Trust
Infrastructure) proposes a "Tamper-Evident Action Recorder" as an example project. This repository builds it
from a design written before any code ([`docs/BLUEPRINT.md`](docs/BLUEPRINT.md)) and measures its limits.

## Reproduce in five minutes

Requirements: Node.js 24 (see `.nvmrc`), a C/C++ toolchain and Python (the `flock` binding is compiled at install
time), Linux with an ext4 or xfs filesystem.
Supported platform: Linux on ext4 or xfs (the specification requires it and the recorder checks the filesystem at
start-up). Built and tested only on Ubuntu 24.04 under WSL2. macOS and native Windows are not supported and were not
tested; on Windows, use WSL2.

```sh
npm ci
npm run build
npm test              # offline: unit tests, the verifier, the frozen fixture
npm run test:tamper   # offline: the §7 tamper matrix and the layer ladder
```

By hand: verify the frozen fixture, then change one word in a copy and verify again.

```sh
npm exec -- tear-verify --log test/fixtures/frozen-m1/events.jsonl --checkpoints test/fixtures/frozen-m1/890c1d36-1e29-45ac-8efc-bdc18c2a34c1/ --tsa-ca-bundle certs/tsa_roots.pem
# VERIFIED_ANCHORED 0..40
# VALID_UNANCHORED 41..50
# ...
```

```sh
# These commands assume a Bash shell (Linux or WSL2): they use mktemp, sed -i and a shell variable.
D=$(mktemp -d) && cp -r test/fixtures/frozen-m1/. "$D"/
sed -i 's/"reason":"baseline"/"reason":"tampered"/' "$D"/events.jsonl
npm exec -- tear-verify --log "$D"/events.jsonl --checkpoints "$D"/890c1d36-1e29-45ac-8efc-bdc18c2a34c1/ --tsa-ca-bundle certs/tsa_roots.pem
# HASH_MISMATCH 25   (exit 1)
```

What needs more than Node.js:

| Command | Needs |
| --- | --- |
| `npm test`, `npm run test:tamper` | Nothing else (both run in CI) |
| `npm run test:pg`, `npm run test:experiments` | A local PostgreSQL (`PGHOST`, `PGDATABASE`, `PGUSER`; default database `tear_test`) |
| `npm run test:local` | The `openssl` command (checks the DER reader against OpenSSL) |
| `npm run m3`, `npm run experiments:b2` | PostgreSQL, network access to the TSAs, and `TEAR_HMAC_PEPPER` (lowercase hex, at least 64 characters, never stored) |
| `npm run report:final-run`, `npm run report:render` | PostgreSQL and `openssl`; they produce `docs/results/` and `docs/REPORT.md` |

`tear-verify` reads only its three inputs (no database, no network) and prints the canonical output of Blueprint
§6b:

| Exit | stdout |
| --- | --- |
| 0 | Coverage and informational lines, for example `VERIFIED_ANCHORED 0..40` then `VALID_UNANCHORED 41..50` |
| 1 | One line with the first failure, for example `HASH_MISMATCH 25` |
| 2 | `INPUT_UNAVAILABLE 0`: an input is missing or unreadable, or the command line is malformed |
| 3 | An internal error, with an explanation on stderr and nothing on stdout; never a successful verification |

### Experiments

- **Layer ladder** (`npm run test:tamper`, offline): the 17 tamper cases seen through four layers of evidence;
  writes `test-results/layer-ladder.md`.
- **Pause exposure**, in two separate runs:
  - **B1** (`npm run test:experiments`, PostgreSQL, offline): the full synthetic dataset of 1000 steps through the
    real interceptor, anchored by an in-process test TSA; writes `test-results/pause-exposure.md`.
  - **B2** (`npm run experiments:b2`, run once): the first 150 application events with real time stamps; its
    artifacts are stored in `experiments/b2/` and analyzed offline by `npm run test:experiments`.
- **Dataset**: `experiments/dataset/traces.jsonl` is synthetic, produced by a script with a fixed seed
  (`scripts/generate-dataset.ts`, mulberry32, seed 20261115). Regenerate it with `npm run dataset:generate`; CI
  checks that the regenerated bytes match the committed file. It does not represent the behavior of any agent or
  model; see [`experiments/dataset/README.md`](experiments/dataset/README.md).

How the code is organized: [`ARCHITECTURE.md`](ARCHITECTURE.md). How the work was split: [`specs/`](specs/).

## Limits

- An anchor at k commits records 0..k only: the tail after the last anchor can be cut or rewritten without
  detection (T3b in the report).
- Against an operator who controls the only copy of the receipts and re-stamps a rewrite inside the time window,
  detection needs receipts held outside the operator's control (T6b).
- Results hold against such an operator only when the bundle `certs/tsa_roots.pem` matches the fingerprint
  published before the first anchor (X2).
- Everything ran on one host (WSL2 on a virtual disk); crashes were simulated, not caused by power loss.
- Certificate revocation is not checked; the profile is offline only.

The complete list, with what was not tested, is in [`docs/REPORT.md`](docs/REPORT.md).
