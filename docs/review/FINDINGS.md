### What I checked and found sound

- **Trust path and precedence.** By inspection, `src/pki/path.ts:32` requires DER identity with a pinned signer, traverses issuers in the bundle, verifies signatures below the root and checks validity at `genTime`, including the root's validity. `src/verify/anchors.ts` checks package identity, structure, signature, commitment, range, agreement with the log and time, in that order. Controls are evaluated after all packages. I found no reversal of that order or path to the system trust store. The treatment of the root's `pathLenConstraint` is explicitly declared an open question in §10.
- **COMMIT and errors.** On the normal path, `callTool` waits for confirmation before invoking the tool and before delivering its result. `finalResponse` awaits the `append`. An uncertain or rolled-back COMMIT produces an error at `src/chain/writer.ts:290`. I found no `catch` that turns that outcome into permission to continue. Finding 3 concerns the identity of the value during that wait.
- **Mutations and independent checks.** The deletion, insertion, swap and recomputation operations appear in `test/tamper/cases.ts`. A verifier that always returned success would fail the negative rows. The two adversaries deliberately produce the same copy for the T3a and T3b suffix cuts. The complete output for the original fixture is also compared with a frozen manifest at `test/unit/frozen-fixture.test.ts:55`. The layer ladder expectations appear in `4121863`, before their implementation in `681af81`.
- **Hygiene and installation.** I verified the published SHA-256 hashes of the Blueprint and the bundle. The lockfile marks `fs-ext@2.1.1` as a package with an install script, and `package.json` expressly authorizes it. The only private-key header found in text patches belongs to the `AAAA` negative vector at `test/unit/bundle.test.ts:73`. The targeted scan found no GitHub tokens or AWS identifiers matching the patterns examined.

### What I did not cover

- **Suites and CLI on the supported environment.** Node returned `v24.22.1`. WSL returned `E_ACCESSDENIED`. I did not run `npm ci`, the build or the suites that write to disk. There are no test counts from this review. The recalculations above were performed in memory on the existing artifacts.
- **Out-of-profile receipts.** The false accepts in finding 2 are inferred from the code. I did not run an end-to-end case, a fuzzing campaign or independent cryptographic validation of every receipt.
- **Durability and the scope of B1/B2.** I did not exercise PostgreSQL, recovery, `SIGKILL`, storage failures or cross-process concurrency. B1 uses the disclosed test TSA. In addition, both B1 and B2 call `beginCall` and `completeCall` with the result taken from the dataset at `test/experiments/replay.ts:61`. Those experiments exercise recording, but they do not exercise invocation of a registered tool through `callTool`.
- **External evidence and history.** I could not establish from Git that the fingerprint had been emailed beforehand or that the suites had been repeated on the published commit. I examined current files and searched for patterns in reachable patches and messages. An audit of transitive dependencies and their binaries, and an exhaustive search for historical secrets, were outside the scope covered.
